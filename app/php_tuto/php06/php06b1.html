Le transfert de fichiers du client vers le serveur (upload en anglais) est une opération de plus en plus courante et extrêmement simple avec PHP.

    Le formulaire client

    Pour que l'utilisateur puisse choisir le fichier à uploader sur son ordinateur nous utilisons un formulaire et une zone de saisie <input> de type file, spécialement conçue pour cet usage. 

    <form method="post" action="page.php" enctype="multipart/form-data">
Choisissez un fichier à uploader :
<input type="file" name="uplFichier">
<input type="submit" name="btnUpload" value="Envoyer">
</form>

    Le tag <form> doit contenir l'attribut enctype avec la valeur multipart/form-data.
    Par défaut, le type d'encodage (enctype) d'un formulaire est application/x-www-forme-urlencoded qui indique que les données saisies dans le formulaire seront transmises au serveur sous la forme de l'encodage des URLs (Zone1=Valeur1&Zone2=Valeur2&...). Ce type est inefficace pour envoyer de grandes quantités de données binaires ou textuelles avec des caractères non-ASCII.

    La RFC2388 (http://www.faqs.org/rfcs/rfc2388.html) définit donc la valeur multipart/form-data pour l'attribut enctype. Cette valeur prévient le serveur que le formulaire va envoyer éventuellement autre chose que des données contenues dans des zones de formulaire, et qu'il peut s'attendre à recevoir de grandes quantités de données textuelles ou binaires (des fichiers par exemple).

    Ensuite, il faut prendre garde à la taille des fichiers uploadés. L'option de configuration upload_max_filesize dans le fichier php.ini détermine la taille maximum d'un fichier uploadé (par défaut : 2 MB). Cette taille peut être réduite ponctuellement si nous ajoutons une zone cachée dans le formulaire :
    <input type="hidden" name="MAX_FILE_SIZE" value="10000">

    Si vous modifiez l'option de configuration upload_max_filesize il faut aussi modifier post_max_size en conséquence.

    Cette zone cachée doit se trouver directement aprés le tag <form>, et doit s'appeler MAX_FILE_SIZE. Sa valeur détermine la taille maximum en octets du fichier qui pourra être uploadé (dans la ligne d'exemple 10000 octets). Si cette valeur est supérieure à la valeur de l'option de configuration upload_max_filesize, elle sera ignorée.

    Le code de notre formulaire devient :

    <form enctype="multipart/form-data" method="post" action="page.php">
<input type="hidden" name="MAX_FILE_SIZE" value="10000">
Sélectionnez le	fichier à uploader :
<input type="file" name="uplFichier">
<input type="submit" name="btnUpload" value="Envoyer">
</form>

    Le code HTML du formulaire pour le côté client est terminé. Nous pouvons maintenant examiner ce qu'il y a à faire du côté serveur pour correctement récupérer et traiter les informations passées par le formulaire.

    Le traitement serveur

    Sur le serveur, les informations sur le fichier transmises par le formulaire seront accessibles dans le tableau superglobal $_FILES, à l'indice 'uplFichier' dans notre exemple. . $_FILES['uplFichier'] est lui même un tableau associatif de 5 éléments :

    name le nom du fichier sur la machine du client.
    type le type MIME du fichier uploadé, tel que déterminé par le navigateur (exemples : application/zip, image/png, video/mp4, application/pdf).
    size la taille en bytes (i.e. octets) du fichier uploadé. Si l'utilisateur essaye d'uploader un fichier dont la taille est supérieure à la limite autorisée, size sera égal à 0.
    tmp_name le nom du fichier temporaire créé sur le serveur. Si l'utilisateur essaye d'uploader un fichier dont la taille est supérieure à la limite autorisée, tmp_name est egal à une chaine vide.
    error code d'erreur
    0 = pas d'erreur / 1 = la taille du fichier dépasse la taille de upload_max_filesize dans php.ini / 2 = la taille du fichier dépasse la taille spécifiée dans le formulaire HTML / 3 = fichier partiellement uploadé / 4 = fichier introuvable.

    La récupération du fichier sur le serveur doit se faire avec 2 fonctions dédiées :

    • is_uploaded_file()
    • move_uploaded_file()

    La fonction is_uploaded_file() prévient des erreurs de transfert et garantit que l'on travaille bien avec un fichier uploadé, et non un fichier "natif" du serveur (prévention contre les risques d'attaques pirates).

    La fonction move_uploaded_file() nous permet de déplacer le fichier uploadé du répertoire d'upload vers son répertoire final sur le serveur. En effet, un fichier uploadé sur le serveur est toujours stocké dans un répertoire temporaire, déterminé par l'option de configuration upload_tmp_dir dans le fichier php.ini. Je vous recommande pour des raisons de sécurité de ne jamais utiliser une fonction de copie de fichier comme copy(), mais de toujours utiliser move_uploaded_file() qui vérifie que le fichier copié est bien un fichier uploadé.

    L'utilisateur système qui exécute les scripts PHP (généralement www-data ou apache) doit avoir la permission d'écriture sur le répertoire dans lequel les fichiers uploadés sont déposés.

    Exemple : upload de fichier

    Vous pouvez remarquer l'utilisation du caractère @ devant certaines fonctions :
    if (! @is_uploaded_file($f['tmp_name'])) {
    et
    if (@move_uploaded_file($f['tmp_name'], $place)) {
    Le caractère @ placé devant une fonction empêche tout message d'erreur éventuel d'être affiché par le navigateur. Dans notre cas, si une erreur se produit, aucune information sur des répertoires ne sera affichée, rendant la page plus sécurisée.

    Pour des raisons de sécurité, il faut contrôler le type du fichier uploadé, et n'autoriser le visiteur qu'à uploader des fichiers du type ou des types attendus. Pour cela, on pourrait penser à utiliser $_FILES['uplFichier']['type']. Par exemple, si on ne souhaite autoriser que l'upload d'images gif, jpg ou png, on pourrait ajouter le bout de code suivant.
    N.B. : ici, on commence par contrôler l'extension du fichier uploadé. 

    // extensions autorisées
$oks = array('.gif', '.jpg', '.png');
$nom = $_FILES['uplFichier']['name'];
$ext = strtolower(substr($nom, strrpos($nom, '.')));
if (! in_array($ext, $oks)) {
    $err = 'extension du fichier non autorisée';
}
// types MIME autorisés
$oks= ['image/gif', 'image/jpeg',
	   'image/pjpeg', 'image/png'];
if ($err == '' && ! in_array($_FILES['uplFichier']['type'], $oks)) {
    // erreur de type de fichier
    $err = 'type de fichier non autorisé';
}

    Mais, la vérification du type MIME avec $_FILES['uplFichier']['type'] est réalisée par le client, et elle n'est pas fiable car il ne teste que l'extension du fichier; il suffit donc de la modifier pour le tromper !
    Il faut donc vérifier le type MIME du fichier uploadé sur le serveur avec la fonction mime_content_type(), qui détecte le type de contenu d'un fichier.

    Problèmes typiques

    Voici quelques problèmes typiques que l'on peut rencontrer lors de l'upload de fichier.

    Pas de fichier uploadé, pas de message d'erreur.
    Le plus souvent c'est dû à la taille du fichier qui dépasse le maximum autorisé par PHP. Testez si un fichier de petite taille (quelque ko) est correctement uploadé.

    Pas de fichier copié, erreur de permission.
    Le script doit avoir les droits d'écriture sur le répertoire final ou le fichier est uploadé.

    Pas de fichier uploadé ou copié, erreurs telles que "open_basedir restriction", "Safe Mode Restriction", "function has been disabled"
    PHP fonctionne en mode sécurisé (Safe Mode), ce qui permet à l'administrateur de contrôler les fonctions qu'un utilisateur a le droit d'exécuter, et d'interdire l'exécution de certaines fonctions (comme la copie ou le transfert de fichiers).
