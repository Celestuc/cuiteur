Quelle que soit la phase de traitement il est primordial de gérer les erreurs qui peuvent se produire avec le serveur de BdD.

Les erreurs empêchant une connexion correcte doivent être traitées immédiatement. Quand une telle erreur se produit, le traitement souhaité ne pourra pas être effectué. Il faut donc afficher une page "propre" et arrêter le script.

Dans l'exemple suivant, nous tentons une connexion avec un mauvais mot de passe pour examiner ce qui se passe dans le cas d'une erreur.

Comme nous pouvons le constater, l'erreur de connexion entraîne la levée d'une exception qui arrête le script. Cela engendre l'affichage d'un message d'erreur au milieu de la page. Pour un utilisateur non averti, ce message est particulièrement déstabilisant et donne une mauvaise image de notre site. Pour un utilisateur averti, et c'est pire, ce message donne des informations sur le serveur de la base de données, et les répertoires du serveur Web, informations qui pourraient être utiles à un pirate cherchant à attaquer notre site.

  • Le nom d'utilisateur de la BdD apparait dans
    Fatal error: Uncaught mysqli_sql_exception: Access denied for user 'tuto_user'@....
  • Le chemin absolu du script PHP exécuté,
    /var/www/localhost/htdocs/php_tuto/test/xxx.php,
    est également indiqué.

Il n'est pas possible de cacher le message d'erreur avec l'opérateur @ car il s'agit d'une erreur critique. Vous pouvez le vérifier en décommentant l'instruction correspondante dans l'exemple ci-dessus.
De toute façon, cacher un message d'erreur ne supprime pas l'erreur !

Suivant le mode de report d'erreur de mysqli, il se peut que l'exécution du script précédent entraîne le déclenchement d'un warning au lieu de lever une exception. Dans ce cas, vous pouvez ajouter l'instruction suivante, avant l'appel de la fonction mysqli_connect(), pour forcer la levée d'une exception si la connexion échoue :
mysqli_report(MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT);

À partir de PHP 8.1.0, la valeur par défaut du mode du rapport d'erreur de mysqli est MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT.

Si la connexion échoue, nous allons pour le moment arrêter le traitement de la page et afficher dans une page "propre" un message facilement compréhensible pour le visiteur.

Quelques généralités sur les exceptions :
- Une exception correspond à un événement anormal ou inattendu qui interrompt le fonctionnement normal d'un programme.
- Une exception est déclenchée -lancée- par une fonction quand une erreur survient lors de son exécution. Un objet de type exception contenant des informations sur l'erreur survenue est alors créé.
- Dès qu'une exception est survenue, le système recherche un bloc de code pour la traiter.

Dans l'exemple ci-dessus, si la connexion échoue, la fonction mysqli_connect() ne retourne pas : une exception mysqli_sql_exception est levée, et comme n'y a pas de bloc pour la traiter, PHP affiche le message d'erreur de l'exception et arrête le script.

Pour traiter cette exception, il faut utiliser une structure de contrôle try, catch. 

try{
	instruction H;
	instruction I;
	instruction J;
	instruction K;
}
catch(mon_exception $e){
	instruction L;
	instruction M;
	instruction N;
}
instruction X;
instruction Y;
...

Les instructions qui risquent d'entraîner la levée de l'exception mon_exception (instructions H, I, J, K), sont placées dans un bloc try. On "essaie" d'exécuter des instructions qui sont susceptibles de lever l'exception mon_exception.

  • Si l'exécution de toutes ces instructions placées dans le bloc try se passe bien (c'est à dire sans lever l'exception mon_exception), les instructions du bloc catch ne sont pas exécutées, et le script poursuit son exécution avec l'instruction qui suit ce bloc catch. Dans ce cas, le script exécute donc les instructions H, I, J, K, X, Y, etc.
  • Si par contre, l'instruction I entraîne la levée de l'exception mon_exception, alors les instructions J et K qui la suivent dans le bloc try ne sont pas exécutées, et le script exécute les instructions du bloc catch. Dans ce cas, le script exécute les instructions H, I, L, M, N, X, Y,

Bien entendu, ce qui précède n'est valide qu'à condition qu'aucune des instructions ci-dessus ne termine le script.

Rappel : l'objet $e de type mon_exception contient des informations sur l'origine de l'erreur qui vient de se déclencher.

Vous trouverez plus d'informations sur les exceptions dans la section "Objets - Les exceptions" à la fin du chapitre consacré aux objets.
