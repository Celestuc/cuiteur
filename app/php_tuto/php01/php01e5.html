Fin de script : exit

    exit met immédiatement fin au script PHP courant et provoque l'envoi de la page telle qu'elle est au navigateur.

    exit peut être employée telle que (i.e. sans parenthèse et sans paramètre), ou avec un paramètre qui peut être une chaîne de caractères ou un entier :

    • si le paramètre transmis à exit est une chaîne, elle sera transmise au navigateur qui l'affichera;
    • si le paramètre transmis à exit est un entier, cette valeur constituera le statut de sortie du script et elle ne sera pas affichée. Le statut de sortie peut être dans l'intervalle 0-255, le statut de sortie 255 est réservé par PHP et ne doit pas être utilisé. Le statut 0 est utilisé pour terminer le programme avec succès.

    die est un alias de exit et peut être utilisé à sa place avec les même règles.

    Niveaux d'erreur

    Quand une erreur se produit dans un script PHP, celui-ci ne sera pas forcément arrêté. Si le niveau de l'erreur n'est pas défini comme fatal, un message d'erreur sera simplement émis par PHP. Suivant la configuration de PHP, les messages d'erreur sont envoyés à la sortie courante (i.e. affiché dans la page) ou stockés dans un fichier. Si l'erreur est une erreur fatale, l'exécution du script s'arrête.

    Il y a 3 niveaux d'erreur dans PHP. Par ordre de gravité décroissante :

    • une erreur fatale est une erreur "grave" qui entraine l'arrêt du script. Exemples : problème d'allocation mémoire, appel d'une fonction avec un nombre insuffisant de paramètres.
    • une erreur warning n'arrête pas le script. Exemples : tentative d'accès à une variable non définie, transtypage d'un tableau en chaîne.
    • une erreur notice, moins grave qu'une erreur warning indique que le script a rencontré quelque chose qui peut être une erreur, mais peut aussi être un événement normal dans la vie du script. Exemple : appel d'une fonction qui sera supprimée dans les futures versions de PHP.

    La fonction error_reporting() permet de définir, pour un script, les erreurs qui seront reportées et pour lesquelles, par défaut, un message sera affiché.

    La fonction accepte comme argument une ou plusieurs constantes combinées avec les opérateurs bit à bit :

    • E_ERROR : erreurs fatales d'exécution provoquant un arrêt du script
    • E_WARNING : erreurs d'exécution sans arrêt du script
    • E_PARSE : erreurs fatales rencontrées lorsque le code PHP est parsé. Exemple : oubli d'un point virgule
    • E_NOTICE : erreurs d'exécution faibles, comparables à des remarques
    • E_CORE_ERROR : erreurs fatales internes de PHP
    • E_CORE_WARNING : erreurs internes de PHP sans arrêt du script
    • E_COMPILE_ERROR : erreurs fatales internes de compilation du Zend Engine
    • E_COMPILE_WARNING : warnings de compilation du Zend Engine sans arrêt du script
    • E_USER_ERROR : comme E_ERROR, mais déclenchée par le développeur dans le code avec trigger_error
    • E_USER_WARNING : comme E_WARNING, mais déclenchée par le développeur dans le code avec trigger_error
    • E_USER_NOTICE : comme E_NOTICE, mais déclenchée par le développeur dans le code avec trigger_error
    • E_STRICT : suggestions visant une meilleure interopérabilité et la compatibilité ascendante du code
    • E_RECOVERABLE_ERROR : erreur fatale "attrapable". Cela indique qu'une erreur probablement grave s'est produite, mais elle ne laisse pas le moteur PHP dans un état instable. Si l'erreur n'est pas attrapée par un gestionnaire défini avec set_error_handler(), le script est arrêté comme si c'était une E_ERROR
    • E_DEPRECATED : erreurs de type E_NOTICE dûes à des instructions dépréciées de PHP (qui seront supprimées dans les versions futures)
    • E_USER_DEPRECATED : comme E_DEPRECATED, mais déclenchée par le développeur dans le code avec trigger_error
    • E_ALL : désigne toutes les erreurs

    Par exemple pour reporter toutes les erreurs d'exécution on appellera la fonction de la façon suivante en utilisant l'opérateur de bit | :

    error_reporting(E_ERROR | E_WARNING | E_PARSE | E_NOTICE);

    Pour reporter toutes les erreurs :

    error_reporting(E_ALL);

    Dans la phase de développement, le recours à l'instruction ci-dessus est utile, car il permet de faciliter le débogage du script.

    Pour supprimer tous les messages d'erreur (excépté les parse error qu'il n'est pas possible de supprimer), utilisez :
    error_reporting(0);

    Lorsque l'opérateur @ (arobase) de contrôle d'erreur est ajouté en préfixe d'une expression PHP, ou d'un appel de fonction, les éventuels messages d'erreur générés sont supprimés.

    Exemple : l'opérateur de contrôle d'erreur @

    Gestionnaire d'erreurs

    Nous pouvons définir, ou installer, notre propre gestionnaire d'erreurs avec la fonction set_error_handler(). Son prototype :
    set_error_handler(?callable $callback, int $error_levels = E_ALL): ?callable

    Paramètres de set_error_handler() :

    • $callback : le nom de la fonction de callback ou handler qui sera appelée automatiquement par PHP lorsqu'une erreur se produira
    • $error_levels : masque permettant de contrôler les types d'erreurs qui seront gérés par la fonction de callback, fonctionne comme le paramètre transmis à la fonction error_reporting()

    La fonction de callback ou handler recevra, quand elle sera appelée, 4 paramètres :

    • code d'erreur (de type int)
    • message d'erreur (de type string)
    • nom du fichier où se produit l'erreur (de type string)
    • numéro de ligne de l'erreur (de type int).

    Redirection des messages d'erreur

    Par défaut les messages d'erreurs sont dirigés vers la sortie courante : la page HTML envoyée au navigateur.

    La fonction error_log() permet de choisir une autre destination pour les messages d'erreurs, et d'en garder une trace. Elle accepte trois arguments : le message d'erreur, la destination du message, et optionnellement une adresse de destination :
    error_log(message, destination [,adresse]);

    • Si destination vaut 0, le message est envoyé dans le fichier d'erreur de PHP, défini dans la configuration de PHP avec l'option error_log.
    • Si destination vaut 1, le message est envoyé à l'adresse e-mail donnée par l'argument adresse. Il faut que votre serveur dispose d'un serveur de mail pour réaliser correctement l'envoi.
    • Si destination vaut 3, le message est ajouté à la fin du fichier dont le nom est donné par l'argument adresse. Le nom de fichier est un nom complet.
