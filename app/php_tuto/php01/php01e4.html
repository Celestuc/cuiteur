Il est possible de déclarer les types des paramètres formels et de la valeur de retour dans l'en-tête d'une fonction.

    Nous vous recommandons de toujours le faire.

    Syntaxe des déclarations de type

    function fct (type1 $param1, type2 $param2) : typeRetour {
  // corps de la fonction
}

    Les types des paramètres formels, et le type de la valeur de retour sont indiqués dans l'en-tête de la fonction. Le type de chaque paramètre formel est tout simplement indiqué avant son nom. Le type de la valeur de retour (ici typeRetour) suit la parenthèse fermante à la fin de la liste des paramètres formels, et est précédé du caractère  :  (deux points).

    Les types simples utilisables sont les suivants : bool, float, int, string, array, object, mixed.
    Le type mixed permet de spécifier que le paramètre ou la valeur de retour peuvent être de n'importe quel type.

    Il est également possible d'utiliser pour le type d'un paramètre formel, ou pour le type de la valeur de retour d'une fonction le nom d'une classe ou d'une interface. Cette possibilité n'est pas traitée dans ce tutoriel.

    Conversion dans le type indiqué

    Dans l'en-tête d'une fonction, quand une déclaration de type précède le nom formel d'un paramètre, les valeurs effectivement transmises sont converties dans le type spécifié à l’entrée dans la fonction (i.e. lors de son appel).

    De même, quand le type de la valeur de retour est indiquée dans l'en-tête d'une fonction, le résultat retourné est converti dans le type indiqué.

    Si ces conversions échouent, une TypeError est lancée : il s'agit d'une erreur fatale qui arrête immédiatement le script.

    Le tableau suivant donne le résultat de ces conversions réalisées par PHP à l'entrée ou à la sortie d'une fonction pour les 4 types scalaires.

    type Valeurs effectivement transmises, ou valeurs "retournées"
    15 17.2 '15' '15a' true false null array(1,2)
    int 15 17 (*) 15 TypeError 1 0 TypeError TypeError
    float 15 17.2 15 TypeError 1 0 TypeError TypeError
    string '15' '17.2' '15' '15a' '1' '' TypeError TypeError
    bool true true true true true false TypeError TypeError

    (*) : La conversion d'une valeur réelle non entière en int (ici 17.2) déclenche une erreur "Deprecated Implicit conversion from float to int loses precision" qui n'arrête pas le script.

    Ces conversions réalisées à l'entrée et à la sortie d'une fonction ne sont pas des transtypages. Par exemple, le transtypage de la chaine '15a' en int donne l'entier 15 et ne lance pas une TypeError.

    Le type void n'est utilisable que pour le type de la valeur de retour d'une fonction (i.e. il ne l'est pas pour le type d'un paramètre). Il indique que la fonction ne renvoie pas de valeur.

    Exemple : Déclaration de type de la valeur de retour

    Avec le type mixed, il n'y a pas de conversion de type effectuée par PHP. Déclarer qu'un paramètre ou une valeur de retour est du type mixed, est fonctionnellement équivalent à ne pas déclarer de type. L'avantage du type mixed est qu'il permet de déclarer explicitement que le paramètre ou la valeur de retour peuvent être de n'importe quel type.

    Le type nullable

    Les déclarations de type peuvent être marquées comme nullable en préfixant le nom du type avec un point d'interrogation (? ). Cela signifie que le paramètre, ou la valeur de retour, peuvent être du type spécifié ou égal à NULL.

    Autre exemple : 

    function f2 (): ?string {
	if (isset($_GET['id'])){
		return 'OK';
	}
	return null;
}

    Les unions de types

    Les unions de types permettent de spécifier qu’un paramètre ou une valeur de retour peuvent être d’un des types de l’union.

    Les unions de types sont spécifiés avec la syntaxe : T1|T2|T3|...

    Le type null peut faire partie de l’union, ce qui permet de créer une union nullable. Exemple : int|float|null

    Le type ?T est donc un raccourci du type T|null.

    null ne peut pas être utilisé comme un type seul.

    Le type littéral false peut également être inclus dans une union de type. Ce type littéral a été ajouté pour des raisons "historiques" étant donné que de nombreuses fonctions PHP retournent le valeur booléenne false, au lieu de retourner null. Exemple : la fonction strpos()

    Le type littéral true a également été ajouté dans PHP8.2.

    Les types littéraux true et false ne peuvent pas être utilisés ensemble dans une union de types. Il faut utiliser le type bool à la place.

    Pour les valeurs de type scalaire, si le type de la valeur n’est pas trouvé dans l’union, son type cible est choisi suivant l’ordre de préférence suivant :
        1. int
        2. float
        3. string
        4. bool

    Le type cible choisi est le premier type existant dans l’union dans lequel la valeur peut être convertie sans lancer une TypeError.

    Il y a une exception à cette règle : si la valeur est une chaîne de caractère numérique et que int et float font partie de l'union, alors le type cible est choisi en fonction des sémantiques de “chaîne numérique”. Par exemple, pour "42" int est choisi, tandis que pour "42.0" float est choisi.

    Exemple : conversions et unions de types

    Le type void ne peut pas faire partie d'une union de types.
    Rappel : le type void est exclusivement un type de valeur de retour.

    Le type mixed est équivalent à l'union de types : object|resource|array|string|int|float|bool|null.
    Rappel : le type mixed indique que le paramètre ou la valeur de retour peuvent être de n’importe quel type.

Dans le corps de la fonction, pour comparer le paramètre $operateur aux chaînes littérales '+' et '*', on peut se contenter d'utiliser l'opérateur de comparaison d'égalité (qui réalise une comparaison non stricte), puisque la conversion de type est, si besoin, réalisée à l'entrée dans la fonction, et que l'on est certain, dans le corps de la fonction, que l'opérateur == est utilisé pour 2 string, dont l'une n'est pas numérique : une comparaison lexicographique est donc réalisée.
