Des instructions permettent d'inclure du code qui se trouve dans des fichiers externes et sont particulièrement utiles pour la constitution et l'utilisation de bibliothèques de fonctions. Il n'y a pas d'applications PHP qui n'utilisent pas d'inclusion de fichiers externes.

    4 instructions pour inclure du code

    Quatre instructions permettent d'inclure des fichiers externes dans un script :

    • include,
    • include_once,
    • require,
    • require_once.

    Chacune des instructions accepte comme paramètre le chemin du fichier à inclure dans la page appelante : 

    include('entete.html');
include_once('fonctions_communes.php');
require('commun/bib_fonctions.php');
require_once('../general/mes_fonctions.php');

    include, include_once, require et require_once sont des constructions du langage particulières et les parenthèses ne sont pas nécessaires autour du paramètre.
    include('entete.html'); est équivalent à include 'entete.html';

    L'extension des fichiers à inclure n'est pas fixée et on peut inclure des fichiers contenant n'importe quel type de code (HTML, CSS, JavaScript et évidemment PHP). Je vous conseille de donner aux fichier à inclure l'extension correspondant à leur contenu : php pour du code PHP, html pour du code HTML, etc. et ne pas utiliser une extension .inc comme c'est parfois le cas.

    Quand le fichier inclus est composé de code PHP, ce code est exécuté.

    Le fichier n'est inclus que si l'instruction include ou require est exécutée. Les inclusions conditionnelles dans des tests if sont donc possibles. Dans ce cas, les blocs du test doivent obligatoirement être entourés d'accolades ({ et }).
    Les inclusions dans des boucles seront faites à chaque itération de la boucle. Si le fichier inclus contient du code PHP qui définit des fonctions, l'inclusion provoquera alors des erreurs dûes à des tentatives de re-définition des fonctions.

    Les instructions include_once et require_once fonctionnent de la même façon que include et require, à la différence qu'elles empêchent le même fichier d'être inclus plusieurs fois dans un même script. Cette fonctionnalité est à utiliser par exemple quand des fichier inclus contiennent eux-même d'autres fichiers inclus. Cela évite que des variables, des constantes, ou des fonctions soient définies plusieurs fois provoquant ainsi des erreurs.

    Les instructions include et include_once déclencheront une erreur de niveau warning si elles ne peuvent pas trouver le fichier; alors que require et require_once déclencheront une erreur de niveau fatal si elles ne peuvent pas trouver le fichier, ce qui arrêtera donc le script.

    Notre bibliothèque de fonctions

    Vous avez pu remarquer que jusqu'à maintenant les exemples de test commencent toujours par la génération du début d'une page HTML. Seul le titre de la page change d'un exemple à l'autre. Pour éviter ces répétitions, nous allons maintenant utiliser une fonction placée dans une bibliothèque (un fichier PHP ne contenant que des définitions de fonctions). De cette façon nous allons simplifier notre code, et, chose extrêmement importante, éviter d'avoir un mélange de langages différents (une couche d'HTML, une couche de PHP, une couche d'HTML, etc.).

    /**
 * Envoie à la sortie standard le début du code HTML d'une page
 *
 * @param string	$titre	Titre de la page
 *
 * @return void
 */
function htmlDebut(string $titre) : void {
	$titre = htmlentities($titre, ENT_COMPAT, 'UTF-8');

	echo '<!DOCTYPE html>',
		'<html lang="fr">',
			'<head>',
				'<meta charset="UTF-8">',
				'<title>', $titre, '</title>',
				'<style>',
				'body {	font-size: 13px;', 
						'font-family: Verdana, sans-serif}',
				'h3 {	font-size: 15px;',
						'margin: 0 0 15px 0;', 
						'padding: 5px 0;', 
						'text-align: center;', 
						'background: #FFF5AB}',
				'h4 {	font-size: 13px;',
						'margin: 1em 0 0 0;',
						'padding: 3px;',
						'background: #ebebeb}',
				'</style>',
			'</head>',
			'<body>',
				'<h3>', $titre, '</h3>';
}

    Le code de la fonction est une simple instruction echo dont les paramètres sont du code HTML sous la forme de chaînes de caractères. Le code HTML est un peu moins simpliste que celui utilisé jusqu'à maintenant car il intégre un minimum de régles de style CSS.

    Le code HTML pourrait être écrit dans une seule valeur littérale. C'est à éviter car dans ce cas beaucoup de caractères sans importance pour le navigateur lui seraient transmis (espaces consécutifs, sauts de ligne, tabulations), à moins de perdre en lisibilité (i.e. en écrivant tout le code HTML sur une seule ligne). Ces caractères inutiles transiteraient sur le réseau et seraient transmis au navigateur alors qu'ils ne servent à rien.
    Utilisée avec comme titre 'Test', la fonction ci-dessus envoie au navigateur 312 octets. Si on avait mis le code HTML dans une seule expression littérale, en gardant la mise en forme pour la lisibilité, on enverrait 452 octets, soit 44% de plus. Le nombre de caractères inutilement transmis est à multiplier par le nombre de visites de la page, et à mettre en relation avec le prix payé à l'hébergeur du site qui facture la bande passante.
    Il est donc particulièrement important de faire transiter sur le réseau des contenus avec la taille la plus petite possible (codes HTML, CSS et JavaScript débarassés des espaces, sauts de ligne et autres tabulations inutiles, fichiers images réduits, etc.). À noter, la description de la fonction sous la forme de commentaires PHPDoc (idem JavaDoc).

    La fonction se trouve dans le fichier bib_fonctions.php, placé dans le dossier de travail.

    Exemple : inclusion de fichier

    Le fichier bib_fonctions.php est complété par la fonction htmlFin() qui génére et affiche le code HTML de fin de page : 

    /**
 * Envoie à la sortie standard la fin du code HTML d'une page
 *
 * @return void
 */
function htmlFin() : void {
	echo '</body></html>';
}

    En ajoutant l'appel de la fonction htmlFin() dans le script précédent, nous obtenons un script PHP qui ne contient plus que du code PHP : tout le code HTML envoyé au navigateur quand il appelle le script est généré par PHP (en utilisant la construction du langage echo).

    Exemple : script PHP avec que du code PHP

    A partir de maintenant, tous les scripts que nous allons écrire ne contiendront plus que du code PHP. Ils débuteront donc par le tag ouvrant <?php (placé au début de la première ligne du script).

    Quand un script ne contient que du code PHP, il est préférable de ne pas fermer l'élément PHP, et donc de ne pas écrire le tag de fermeture ?>, pour éviter que d'éventuels caractères d'espaces blancs placés après ce tag de fermeture soient "interprétés" comme du code HTML.

    Commentaires PHPDoc

    Vous devez décrire, dans votre code, toutes les fonctions que vous définissez, avec une documentation PHPDoc. Cette bonne pratique vous permettra de savoir ce que fait votre fonction sans avoir à éplucher le code, et elle vous permettra d'indiquer la signification des différents paramètres et de la valeur de retour.

    Une documentation PHPDoc se présente comme suit : 

    /**
 * Description courte de la fonction
 *
 * Eventuelle description détaillée de la fonction
 * sur plusieurs lignes
 *
 * @param 	type1 	$nom1 	description de $nom1
 * @param 	type2 	$nom2	description de $nom2
 *
 * @return 	typeRetour	description de la valeur de retour
 */
function foobar(type1 $nom1,type2 $nom2): typeRetour { … }

    Un bloc de commentaires PHPDoc commence par un slash suisi de 2 étoiles (/**), et se termine par une étoile suivie par un slash (*/).
    Chaque ligne de la documentation PHPDoc entre la première et la dernière ligne commence par une étoile (*).

    Le contenu est divisé en 3 ou 4 "parties" séparées par une ligne vide :

    • La première partie, sur une ligne, contient une description courte (i.e. un résumé) de ce que la fonction fait.
    • La seconde partie, optionnelle, donne une description détaillée de la fonction.
    • Ensuite, on trouve la description des paramètres, un par un, suivant le format indiqué. Notez l'utilisation du tag @param.
    • La documentation PHPDoc se termine par la description de la valeur de retour de la fonction suivant le format indiqué. Notez l'utilisation du tag @return.

    Exercice : bibliothèque de fonctions

    Ecrivez une bibliothèque avec les fonctions suivantes :

    - la fonction debutHtml() permet de renvoyer tout le code HTML du début d'une page : 

    <!DOCTYPE html>
<html lang="fr">
  <head>
    <title>Titre de la page</title>
  </head>
  <body>

    Cette fonction accepte deux paramètres : le titre de la page (tag TITLE) et la couleur de fond de la page. Si aucune couleur de fond n'est passée, la valeur par défaut du paramètre est '#FFFFFF'.

    - la fonction tableHtml() renvoie une chaîne de caractères avec le code HTML d'un élément TABLE, contenant (ou encapsulant) les chaînes de caractères qui lui passées en paramètres. Le nombre de colonnes de la TABLE sera variable, et déterminé par un des paramètres. Il faut prévoir aussi des paramètres qui permettent de gérer les couleurs : couleur de fond de la TABLE, couleur de fond de ligne pour faire un affichage différencié une ligne sur deux. Ces paramètres sont obligatoires. La table HTML doit avoir une ligne d'en-tête et au moins une ligne de "données". Si des paramètres ne sont pas en bon nombre, un message doit être renvoyé pour signaler l'erreur.

    - la fonction finHtml() renvoie le code HTML qui termine une page. Le pied de page est composé d'une ligne avec le nom de l'auteur de la page (à passer en paramètre à la fonction).

    Ces trois fonctions doivent se trouver dans le fichier bibli_html.php.

    Ecrivez le script test.php qui génére une page HTML en utilisant ces trois fonctions.

    Une solution possible

    Le fichier bibli_html.php avec les 3 fonctions demandées. 

    <?php
/**
 * Renvoie le code HTML du début d'une page
 *
 * @param string    $titre      Titre de la page
 * @param string    $couleur    Couleur de fond de la page
 *
 * @return string   Code HTML du début d'une page
 */
function debutHtml(string $titre,
				   string $couleur='#FFFFFF') : string {
  return '<!DOCTYPE html><html lang="fr"><head>'
        .'<title>'.$titre.'</title>'
        .'<style>body{background-color:'.$couleur.'}</style>'
		.'</head><body>';
}

/**
 * Renvoie le code HTML d'une table.
 *
 * @param integer   $nbCol      Nombre de colonnes
 * @param string    $coulFond   Couleur de fond de la table
 * @param string    $coulLigne  Couleur d'une ligne sur 2
 * @param string ...$chaines	Chaînes à afficher
 *
 * @return string   Code HTML de la table ou message d'erreur
 */
function tableHtml(int $nbCol, string $coulFond,
                   string $coulLigne,
                   string ...$chaines) : string {
  if ($nbCol < 1) {
    return 'Mauvais nombre de colonnes';
  }
  if ($coulFond ==  '' || $coulLigne == '') {
    return 'Mauvaise couleur';
  }
  //--- Bon nombre d'arguments ?
  $nbChaines = count($chaines);
  if ($nbChaines % $nbCol != 0) {
    return 'Mauvais nombre d\'éléments pour la table';
  }
  if ($nbChaines < ($nbCol * 2)) {
    return 'Pas assez d\'éléments pour faire au moins
            un en-tête et une ligne';
  }

  //--- Début table html ------------------------
  $html = '<table style="text-align:center; background-color:'.
          $coulFond.'">';
  $numLig = 0;
  //--- Boucle de traitement des arguments -------
  // on commence au 3 éme
  for ($i = 0; $i < $nbChaines; $i += $nbCol) {
    $numLig ++;
    //--- Nouvelle ligne
    if ($numLig % 2 == 0) {
      $html .= '<tr>';
    } else {
      $html.= '<tr style="background-color:'.$coulLigne.'">';
    }
    //--- Les celulles
    for ($j = 0; $j < $nbCol; $j++) {
      $html .= '<td style="width:'.floor(100/$nbCol).'px">'
              .$chaines[$j + $i].'</td>';
    }
    $html .= '</tr>';
  }
  $html .= '</table>';
  return $html;
}
/**
 * Renvoie le code HTML de fin d'une page
 *
 * @param string    $auteur     Nom de l'auteur
 *
 * @return string   Code HTML de fin d'une page
 */
function finHtml(string $auteur) : string {
  return '<hr><p>'.$auteur.'</p>'
        .'</body></html>';
}
