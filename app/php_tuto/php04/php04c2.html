Parenthèses non capturantes

    Dans certains cas nous ne voulons pas capturer tous les sous-motifs entre parenthèses, mais les parenthèses sont néanmoins nécessaires dans la syntaxe de l'expression.

    Soit le texte :
    "Il y a bien longtemps, dans une galaxie lointaine, l'Empire Impérial de l'Empereur triomphe sur tous les fronts, broyant tous ceux qui s'opposent à lui d'une main de fer dans un gant d'acier. Seul un petit groupe de rebelles se bat toujours pour la liberté face à la tyrannie, pour le chaos face à l'ordre, et d'abord on fait c'qu'on veut merde !"

    Si nous voulons récupérer tous les mots qui suivent des articles définis ou indéfinis (le, la, les, l', un, une et des), en minuscule ou en majuscule, nous pouvons utiliser l'expression :
    /\b(les?|la|l'|une?|des)\s*\b(\w+)/i
    Entre l'article (défini ou indéfini) et le mot recherché, il peut y avoir un nombre quelconque d'"espaces blancs", y compris aucun dans le cas de l'article l', d'où l'utilisation de \s*. Dans tous les cas, le premier caractère du mot recherché doit correspondre à un début de mot, d'où l'utilisation de l'assertion \b. Sans cette assertion, la chaîne lequel, par exemple, correspondrait au pattern complet.

    Exemple : capture de tous les sous-motifs

    Ici, il est préférable d'utiliser la constante prédéfinie PREG_PATTERN_ORDER que la constante PREG_SET_ORDER

    L'expression fonctionne, mais nous avons capturé aussi les articles définis ou indéfinis alors que nous voulons seulement le mot qui les suit. Ici, nous pouvons rendre les parenthèses non capturantes, en ajoutant simplement ?: après la parenthèse ouvrante :
    /\b(?:les?|la|l'|une?|des)\s*\b(\w+)/i

    Le résultat du test montre bien que les articles définis ou indéfinis n'ont pas été capturés comme dans l'avant-dernier exemple.

    Références arrières

    La capture avec des parenthèses est une capture mémorisante : la chaîne qui correspond au sous-motif est gardée en mémoire par le moteur d'expressions régulières et pourra servir à nouveau, ou être rappelée, dans la suite de l'expression.
    On appelle cela une référence arrière (backreference en anglais). Pour rappeler la chaîne correspondant à un sous-motif, on utilise un backslash, suivi d'un numéro spécifiant le rang du sous-motif dans le pattern (i.e. \1, \2, etc.).

    Nous avions précédemment utilisé l'expression régulière suivante pour vérifier un format de date :
    /^(\d{1,2}[\/\-. ]){2}\d{2,4}$/
    Mais cette expression ne permettait pas de détecter l'utilisation de 2 séparateurs autorisés différents, entre le jour et le mois, et entre le mois et l'année. Par exemple, la chaîne 17/2-2022 correspond au pattern ci-dessus. En utilisant une référence arrière, il devient possible de détecter ce problème tout en autorisant les mêmes séparateurs entre les trois champs de la date :
    /^\d{1,2}([\/\-. ])\d{1,2}\1\d{2,4}$/
    Pour qu'une chaîne corresponde à ce pattern, il faut que le deuxième séparateur (celui entre le mois et l'année) soit exactement égal à celui qui a été capturé par le premier et unique sous-motif du pattern.

    Exemple : référence arrière

    Un des exemples typiques du fonctionnement des références arrières consiste à rechercher si une chaîne contient le même mot répété 2 fois de suite. Pour rechercher un mot nous aurons l'expression régulière suivante :
    \b(\w+)
    Soit un début de mot (\b), suivi de 1 ou plusieurs caractères de mot (\w+). Les parenthèses autour de \w+ permettent de capturer le mot trouvé.
    Et \1 permet de le référencer dans la suite de l'expression.
    L'expression /\b(\w+)\s+\1\b/ permet donc de rechercher un même mot répété 2 fois de suite; les 2 occurences du mot devant être séparés par un ou plusieurs "espaces blancs".

    Exemple : référence arrière

    Ne pas mettre de quatrième argument à la fonction preg_match_all()équivaut à utiliser PREG_PATTERN_ORDER

    L'exemple suivant permet d'extraire d'un code HTML tous les textes entourés par les tags <b> ou <i> avec l'expression :
    #<([bi])>(.*?)</\1>#is;

    <([bi])> recherche les chaînes comme <b> et <i>, et capture le b ou le i, que nous réutilisons pour définir la balise fermante : </\1>

    Comme cette expression contient un /, nous utiliserons le caractère # comme délimiteur de l'expression régulière.

    Comme les textes entourés par les tags <b> ou <i> peuvent contenir des sauts de lignes, nous utilisons l'option s.

    Exemple : référence arrière

    Pendant que nous sommes dans les tags HTML, voilà une expression régulière qui permet de capturer tous les tags HTML, ouvrants ou fermants, qu'ils aient ou non des attributs :
    #</?(\w+)[^>]*>#

    Pour extraire les textes entourés par n'importe quel tag HTML et le nom du tag, nous aurons l'expression :
    #<(\w+)[^>]*>(.*?)</\1>#s

    Attention, dans le cas de tags imbriqués, cette expression ne capturera que le tag le plus englobant de l'imbrication.

    Une solution possible

    Exercice : extraire les liens d'une page HTML

    La première solution /\bhref\s*=\s*"(.*?)"/is est fausse pour deux raisons :
    - elle capture des liens en trop qui sont non cliquables (feuilles de styles par exemple);
    - la valeur de l'attribut href peut aussi être entourée de simples quotes.

    Il est possible d'utiliser l'expression régulière suivante :
    /<a\b[^>]+href\s*=\s*(['"])\s*(\S*?)\s*\1/i

    <a la chaîne littérale <a
    \b assertion correspondant à une fin de mot
    [^>]+ un plusieurs caractères qui ne peuvent pas être un >
    href la chaîne littérale href
    \s* 0 ou plusieurs caractères "espaces blancs"
    = la chaîne littérale =
    \s* 0 ou plusieurs caractères "espaces blancs"
    (['"]) expression atomique qui doit être égal soit à un guillemet simple, soit à un guillemet double. La valeur du caractère correspondant est capturée et est référencée ultérieurement dans le pattern par \1
    \s* 0 ou plusieurs caractères "espaces blancs". La valeur de l'attribut href peut contenir des "espaces blancs" juste après le guillemet ouvrant, et juste avant le guillemet fermant
    (\S*?) 0 ou plusieurs caractères qui ne peuvent pas être des "espaces blancs", avec capture de la valeur du lien (Un lien ne peut pas contenir d'"espaces blancs").
    *? : quantificateur non gourmand
    \s* 0 ou plusieurs caractères "espaces blancs"
    \1 la correspondance capturée par (['"])
    i Option i : les noms des tags HTML et des attributs ne sont pas sensibles à la casse
