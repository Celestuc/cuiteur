Dans une application réelle, en cas d'erreur(s) (de type visiteurs "distraits"), il faut afficher les messages d'erreur et réafficher le formulaire avec les zones remplies par la saisie précédente de l'utilisateur (pour qu'il puisse voir et corriger ses erreurs). Pour que cela soit possible, il faut que la génération du code HTML du formulaire ET la soumission du formulaire soient faites dans le même script, et mettre en oeuvre une auto-soumission du script.

    Le traitement à réaliser varie suivant deux cas :

    • Le premier cas est celui où l'utilisateur arrive sur la page pour la première fois : il faut alors afficher un formulaire "vide".
    • Le deuxième cas est celui où l'utilisateur a rempli le formulaire et l'a envoyé pour traitement. Ici il faut vérifier la validité de la saisie :
      • Si tout est OK on réalise en général un traitement sur la base de données et on redirige l'utilisateur vers une autre page. Dans le script ci-dessous, on se contentera d'afficher un message indiquant que la redirection.
      • Si des erreurs ont été détectées, il faut afficher les messages d'erreur et réafficher le formulaire avec les zones remplies par la saisie précédente de l'utilisateur.

    Pour réaliser cela, le script traite l'éventuelle soumission du formulaire avant de l'afficher.

    Comme on souhaite que nos scripts PHP ne contiennent que du code PHP, le code HTML du formulaire est ici généré par PHP en utilisant l'instruction echo

    Exemple : gestion des erreurs de saisie

    Quelques explications sur le code du script.

    // erreurs détectées lors de la soumission
$erreurs = [];

    Le script commence par initialiser un tableaux destiné à contenir les erreurs détectées (vide au départ). 

    // si soumission du formulaire
if (isset($_POST['btnEnvoi'])){
    $erreurs = traiteSoumission();
}

    Nous testons ensuite si le script est appelé suite à une soumission du formulaire, ou bien s'il est appelé pour un premier affichage, en testant la présence dans le tableau $_POST de la clé btnEnvoi correspondant au bouton submit.
    Lors du premier appel, le script est appelé via une requête HTTP GET, donc, à l'entrée dans le script, le tableau $_POST est vide.
    Lorsque le visiteur clique sur le bouton submit, le script est appelée via une requête HTTP POST, et si le code HTML du formulaire n'a pas été modifié; le tableau $_POST, à l'entrée dans le script, contient 4 éléments ayant pour clés btnEnvoi, txtNom, txtRq et numId.
    Donc la fonction traiteSoumission() n'est bien appelée qu'en cas de soumission du formulaire.

    Si la fonction de traitement de la soumission, traiteSoumission(), détecte une tentative de piratage, ou si elle ne détecte aucune erreur, le script est arrêté avant qu'elle ne retourne. On ne retourne donc de la fonction que s'il n'y a pas de tentative de piratage détectée et qu'on a détecté des erreurs. Dans ce cas, les erreurs sont renvoyées.

    Notez que la fonction afficherForm() utilise l'élément de clé PHP_SELF du tableau $_SERVER pour réaliser une auto-soumission : la valeur de $_SERVER['PHP_SELF'] est égale au chemin vers le script en train de s'exécuter.

    Remarquez l'utilisation de la fonction htmlentities() qui permet d'assurer une protection contre les éventuelles attaques XSS réfléchies.
    Pour vous convaincre de l'utilité de cette protection, commentez les 4 lignes correspondantes, tester le script, et saisissez, dans l'input de type text :
    "><img src="http://www.deguisement.fr/img/p-deguisement.fr/232-309-thickbox.jpg">
    puis soumettez le formulaire.

    Vous pouvez aussi saisir par exemple :
    "><script>location="http://google.fr"</script>

    Pour que l'"attaque XSS" fonctionne dans le textarea, vous pouvez par exemple saisir :
    </textarea><script>location="http://google.fr"</script>

    Le simple affichage de la chaîne reçue du formulaire provoque, si elle contient des tags HTML, l'exécution du code saisi par l'utilisateur. Cela constitue une faille de sécurité béante ! La fonction htmlentities() renvoie une chaîne où le code HTML, éventuellement présent dans la chaîne qu'on lui transmet en paramètre, est neutralisé.
